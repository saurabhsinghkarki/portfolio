Background 1440 × 320
01 · Context

The pain of manual code deployments under pressure

Simplotel powers thousands of hotel websites where hoteliers regularly request short-term banner changes, flash vouchers, alert notices, or regulatory messages. Previously, launching a popup for a website required a developer to manually construct HTML containers, write custom CSS alignments, code event listeners for exit-trigger animations, and build session storage constraints.

This laborious process had several major drawbacks: it consumed 1 to 2 hours of developer time per request, had a high rate of copy-paste formatting errors that broke responsive layout views, and often failed basic accessibility parameters (like allowing keyboard users to exit or trapping focus inside modal boundaries). We needed a unified automation script that could build popups from a clean metadata config in minutes.

02 · Layout Matrix

Flesh out the combination matrix

By examining over fifty historical popup requests, we discovered that they all fell into a clean matrix of logical combinations. Standardizing these motifs allowed us to build specific configurations for every scenario:

✦ Display Layouts

  • Image Banner (wt1img): Clean picture link matching custom resolutions.
  • Editorial Content (custom-text): Title heading, paragraph blurb, call-to-action button.
  • Video Promos (wt1video): Inline playing video files with mute/loop overlays.

✦ Targets & Scopes

  • Single Property: Target one hotel ID within a group.
  • Multi-Property (Shared): Generic banner applied across all group properties.
  • Multi-Property (Distinct): Diverse banners/links parsed specifically per hotel ID dynamically.

✦ Triggers & Timing

  • Exit Intent: Mouseout listener targeting top screen bounds.
  • Timed Delay: Delayed window event execution (e.g., 4000ms).
  • Page Scroll: Appears when consumer reaches intermediate depth.

03 · Coding The Engine

Standardizing the injection logic

The engine operates by parsing a JSON configuration object on layout load. In the background, it generates frequency-capping tags and injects the modal directly into the pages.

// Dynamically track and constrain display to once per property session
const sessionKey = "popup_shown_" + (hotelId || "default");
if (sessionStorage.getItem(sessionKey)) return;

// Set session cap on first popup view
const showPopup = () => {
  sessionStorage.setItem(sessionKey, "true");
  popUpBody.style.display = "flex";
  popUpBody.setAttribute("aria-hidden", "false");
  popUpBody.focus();
};

By prefixing storage sessions with hotelId, the cookie constraint operates perfectly even inside dynamic corporate portals that manage multiple hotel properties on the same domain name. This prevents annoying over-prompting and preserves customer browsing trust.

07 · Reflections

Key takeaways from standardizing UI patterns

Standardizing common visual elements in a product catalog isn't just about saving time - it alters the way a software engineering department functions. By taking the time to outline combinations and construct a metadata-driven generator, we transformed a slow, manual task into a simple configuration form that anyone on the team can fill out.

Integrating accessibility rules (A11y rules) directly into the code templates highlighted the benefits of shifting standards left. Instead of educating every single designer and junior engineer on coding keyboard trap loops and focus states for each custom request, encoding it into the generator means every new popup created inherits ADA compliance automatically.

Ultimately, automation shifts focus to where it brings the most value. Slicing deployment time by over 90% eliminated developer fatigue from redundant coding tasks, allowing the engineering team to focus on building features for the core Simplotel booking platforms.
